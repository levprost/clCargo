# Этап 3. Изображение и адаптивность

В assets/mobile-banner лежит предоставленный заказчиком квадратный баннер. Его исходный размер 1254×1254px. Экспорты одинаковой композиции: 320, 480, 640, 768, 960 и 1254px, каждый в WebP и JPEG. Оригинальный PNG также сохранён. Не увеличивай изображения сверх исходного разрешения и не перерисовывай надписи.

Изменение относится к мобильному варианту hero (<=1030px): этот баннер заменяет прежнюю фотографию и располагается первым элементом блока, над бейджем опыта, H1 и всем остальным. Шапка сайта остаётся выше hero. Между шапкой и баннером небольшой обычный отступ 16–24px. Ни текста, ни преимущества, ни девиза над баннером внутри hero быть не должно.

Полный мобильный порядок:
баннер → бейдж опыта → H1 → вводный абзац → страны → подробный абзац → кнопка расчёта → кнопка менеджера → девиз с пояснением → преимущества.

На десктопе (>1030px) сохрани утверждённую композицию и тематическую фотографию справа. Баннер заказчика нужен только мобильной версии; не заменяй им правое фото десктопа без отдельного указания. Если отдельного desktop-фото нет в проекте, сообщи об отсутствии файла; не выдавай скриншот hero с текстом за фотографию. PNG в references — именно макеты, не готовые картинки для вставки в hero.

Подключи баннер через srcset/sizes и picture с WebP и JPEG fallback либо эквивалентный существующий механизм WordPress. Пример перечня WebP:
cl-cargo-mobile-320.webp 320w,
cl-cargo-mobile-480.webp 480w,
cl-cargo-mobile-640.webp 640w,
cl-cargo-mobile-768.webp 768w,
cl-cargo-mobile-960.webp 960w,
cl-cargo-mobile-1254.webp 1254w.

Ширина отображения на <=1030px: calc(100vw - 32px), при боковых отступах 16px. Если контейнер получил другие реальные отступы, синхронизируй sizes. Учитывай плотность пикселей: не выбирай файл только по ширине окна через JavaScript. Браузер должен сам выбрать кандидат srcset.

Для picture можно задать мобильные source media='(max-width: 1030px)' с WebP и JPEG, а desktop-фото оставить fallback img. Сам media-элемент первым в DOM; на десктопе расположи его справа CSS Grid, на мобильном оставь первым. Обеспечь соответствие адаптивного соотношения сторон: мобильный баннер 1/1, десктопное фото по его реальным размерам. Не задавай растягивающий фиксированный height всему picture.

Мобильное изображение: display:block; width:100%; height:auto; aspect-ratio:1/1. Полная композиция должна быть видна. Нельзя обрезать логотип, надписи, самолёт, контейнер, телефон или нарисованную кнопку; не используй cover для квадратного баннера в неквадратном контейнере. Задай корректные intrinsic width/height или зарезервируй нужное место CSS, чтобы не было скачка вёрстки.

Баннер — первый заметный элемент на телефоне: не применяй к нему lazy-loading. Для основного изображения hero используй подходящий высокий приоритет; не делай несколько независимых высокоприоритетных загрузок скрытых дублей. Проверяй фактическую загрузку desktop/mobile, а не только display:none.

На баннере нарисована кнопка расчёта. Сделай весь мобильный баннер одной ссылкой к существующему калькулятору. Используй локализованный bannerLinkLabel и bannerAlt из content.json. Не имитируй отдельные кликабельные кнопки и телефон случайными координатными hotspot-областями. Настоящие HTML-кнопки hero и контактное окно остаются доступными ниже.

Украинские надписи встроены в растр и остаются такими при выборе RU. Язык HTML вокруг баннера, aria-label и alt переключается. Не утверждай, что изменение alt переводит саму картинку. Для отдельного русского баннера потребуется другой графический файл; здесь он не предоставлен. Полная транскрипция баннера и русский перевод для будущей графической версии находятся в banner-copy.md.

На мобильном CTA в одну колонку на всю ширину. Все элементы участвуют в нормальном потоке. Меняй число колонок преимуществ и чипов по месту; не маскируй переполнение глобальным overflow-x:hidden.
